## 2. Criação de Conta

**Definição:** Total de eventos `user_registered` no período.

**Query HogQL:**
```sql
SELECT multiIf(
  toDate(timestamp) BETWEEN '2026-07-20' AND '2026-07-23', 'WTD Atual',
  toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19', 'W-1',
  toDate(timestamp) BETWEEN '2026-07-06' AND '2026-07-12', 'W-2',
  toDate(timestamp) BETWEEN '2026-06-29' AND '2026-07-05', 'W-3',
  'out'
) as week,
count() as total
FROM events
WHERE event = 'user_registered'
  AND toDate(timestamp) >= '2026-06-29'
  AND toDate(timestamp) <= '2026-07-23'
GROUP BY week
ORDER BY week ASC
```

## 4. WAC (Weekly Active Contributors)

**Definição:** Usuários únicos que publicaram ao menos um review ou foto na semana.

**Query HogQL:**
```sql
SELECT multiIf(
  toDate(timestamp) BETWEEN '2026-07-20' AND '2026-07-23', 'WTD Atual',
  toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19', 'W-1',
  toDate(timestamp) BETWEEN '2026-07-06' AND '2026-07-12', 'W-2',
  toDate(timestamp) BETWEEN '2026-06-29' AND '2026-07-05', 'W-3',
  'out'

count(DISTINCT distinct_id) as wac
FROM events
WHERE event IN ('review_submitted', 'review_flow_photo_added')

ORDER BY week ASC
```

## 5. SIR v1 (Social Interaction Rate)

**Definição:** Reviews distintos com ≥1 interação (like, reação ou comentário) / total de reviews submetidos × 100.

**Racional:** Cada review conta UMA VEZ no numerador, independente de quantas interações recebeu. `review_id` extraído via `JSONExtractString(properties, 'review_id')`.

**Limitação:** W-1 > 100% ocorre porque interações podem ser em reviews de semanas anteriores (não temos `created_at` da review no evento de interação). Resolve-se no PostgreSQL cruzando `review_likes.created_at` com `user_reviews.created_at`.

**Query HogQL:**
```sql
SELECT week,
  reviews_interacted,
  total_reviews,
  round(reviews_interacted * 100.0 / total_reviews, 1) as sir_pct
FROM (
  SELECT week,
    count(DISTINCT review_id) as reviews_interacted,
    sum(total_reviews) as total_reviews
  FROM (
    -- Numerador: reviews que receberam interação
    SELECT multiIf(
      toDate(timestamp) BETWEEN '2026-07-20' AND '2026-07-23', 'WTD Atual',
      toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19', 'W-1',
      toDate(timestamp) BETWEEN '2026-07-06' AND '2026-07-12', 'W-2',
      toDate(timestamp) BETWEEN '2026-06-29' AND '2026-07-05', 'W-3',
      'out'
    ) as week,
    JSONExtractString(properties, 'review_id') as review_id,
    0 as total_reviews
    FROM events
    WHERE event IN ('review_reacted', 'review_liked', 'comment_posted')
      AND toDate(timestamp) >= '2026-06-29'
      AND toDate(timestamp) <= '2026-07-23'
    
    UNION ALL
    
    -- Denominador: total de reviews submetidos
    SELECT multiIf(
      toDate(timestamp) BETWEEN '2026-07-20' AND '2026-07-23', 'WTD Atual',
      toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19', 'W-1',
      toDate(timestamp) BETWEEN '2026-07-06' AND '2026-07-12', 'W-2',
      toDate(timestamp) BETWEEN '2026-06-29' AND '2026-07-05', 'W-3',
      'out'
    ) as week,
    NULL as review_id,
    1 as total_reviews
    FROM events
    WHERE event = 'review_submitted'
      AND toDate(timestamp) >= '2026-06-29'
      AND toDate(timestamp) <= '2026-07-23'
  )
  GROUP BY week
)
ORDER BY week ASC
```

## 6. Content Creation Rate

**Definição:** (reviews criados + listas criados) / WAC no período. Não é porcentagem — é volume médio de conteúdos por contribuidor.

**Query HogQL:**
```sql
SELECT multiIf(
  toDate(timestamp) BETWEEN '2026-07-20' AND '2026-07-23', 'WTD Atual',
  toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19', 'W-1',
  toDate(timestamp) BETWEEN '2026-07-06' AND '2026-07-12', 'W-2',
  toDate(timestamp) BETWEEN '2026-06-29' AND '2026-07-05', 'W-3',
  'out'
) as week,
countIf(event = 'review_submitted') as reviews,
countIf(event = 'restaurant_saved_to_collection') as lists
FROM events
WHERE event IN ('review_submitted', 'restaurant_saved_to_collection')
  AND toDate(timestamp) >= '2026-06-29'
  AND toDate(timestamp) <= '2026-07-23'
GROUP BY week
ORDER BY week ASC
```

**Cálculo:** `(reviews + lists) / WAC_da_mesma_semana`

## 7. New User

**Definição:** Usuários cuja primeira sessão (`Application Opened`) ocorreu na semana analisada.

**Query HogQL (uma por período):**
```sql
SELECT count()
FROM (
  SELECT distinct_id, min(toDate(timestamp)) as first_open
  FROM events
  WHERE event = 'Application Opened'
    AND toDate(timestamp) >= '{data_inicio}'
    AND toDate(timestamp) <= '{data_fim}'
  GROUP BY distinct_id
  HAVING first_open BETWEEN '{data_inicio}' AND '{data_fim}'
)
```

| Período | data_inicio | data_fim |
|---------|-------------|----------|
| W-3 | 2026-06-29 | 2026-07-05 |
| W-2 | 2026-06-29 | 2026-07-12 |
| W-1 | 2026-06-29 | 2026-07-19 |
| WTD Atual | 2026-06-29 | 2026-07-23 |

**Nota:** A data de início da subquery é sempre o início do range histórico (29/jun) para capturar usuários cujo primeiro acesso foi antes mas caíram no `HAVING` da semana correta.

## 9. Retenção D1 / D7 / D15 / D30

**Definição:** % de usuários ativos na semana que retornaram D+N dias após seu primeiro acesso naquela semana.

**Racional:** Para cada usuário ativo na semana, pega-se `min(toDate(timestamp))` como `first_active`. Verifica-se existência de evento `Application Became Active` em `first_active + N`. Cada D é independente (não acumulativo).

**Query HogQL (exemplo W-1 com D1 e D7):**
```sql
SELECT
  count(DISTINCT w.distinct_id) as total,
  count(DISTINCT e1.distinct_id) as d1,
  count(DISTINCT e7.distinct_id) as d7
FROM (
  SELECT distinct_id, min(toDate(timestamp)) as first_active
  FROM events
  WHERE event = 'Application Became Active'
    AND toDate(timestamp) BETWEEN '2026-07-13' AND '2026-07-19'
  GROUP BY distinct_id
) w
LEFT JOIN events e1 ON e1.distinct_id = w.distinct_id
  AND e1.event = 'Application Became Active'
  AND toDate(e1.timestamp) = w.first_active + 1
LEFT JOIN events e7 ON e7.distinct_id = w.distinct_id
  AND e7.event = 'Application Became Active'
  AND toDate(e7.timestamp) = w.first_active + 7
```

**Disponibilidade por período:**

| Período | D1 | D7 | D15 | D30 |
|---------|-----|-----|------|------|
| W-3 | ✅ 30/jun–06/jul | ✅ 06–12/jul | ✅ 14–20/jul | 🔮 29/jul–04/ago |
| W-2 | ✅ 07–13/jul | ✅ 13–19/jul | ✅ 21–27/jul | 🔮 05–11/ago |
| W-1 | ✅ 14–20/jul | ✅ 20–26/jul | 🔮 28/jul–03/ago | 🔮 |
| WTD Atual | ⚠️ 21–24/jul (parcial) | 🔮 | 🔮 | 🔮 |

**Nota:** WTD Atual D1 subestima (8.7%) porque usuários de 23/jul têm D+1 futuro e ingestion lag afeta os dias mais recentes.

## Capacidades e Limitações

| Capacidade | Fonte | Limitação |
|-----------|-------|-----------|
| Métricas de aquisição/ativação | PostHog (HogQL) | Sem downloads (App Store) |
| Métricas de engajamento | PostHog (HogQL) | Sem `content_id` em eventos de visualização |
| SIR com `review_id` | PostHog (`JSONExtractString`) | Pode >100% (reviews antigas no numerador) |
| Retenção por evento | PostHog (JOIN + subquery) | Aproximação; não é coorte clássica |
| Comentários | PostHog (`comment_posted`) | Volume baixo (24 eventos em 30 dias) |
| Dados transacionais | PostgreSQL (restu-web) | Sem acesso direto; tabelas não estão no Databricks |
