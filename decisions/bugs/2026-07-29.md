# Bug Triagem — 2026-07-29

## Deep link de restaurante sem ID curto quebra no app

**Severidade:** HIGH
**Reportado por:** Paulo Moreira (Slack)
**Fluxo:** compartilhamento → descoberta (core)

### Descrição
Links de restaurante no formato simplificado (ex.: `gomoapp.com.br/restaurante/babbo-osteria`) funcionam na web mas retornam "restaurante não encontrado" no app mobile.

### Causa raiz
1. API `GET /api/restaurantes/[id]` busca apenas por UUID: `WHERE id = :param`. Slug puro → 404.
2. App mobile (React Navigation linking) extrai `restaurantId = "babbo-osteria"` e passa direto pra API sem tradução slug→UUID.

### Evidências
- Restaurante Babbo Osteria: `cef44971-a389-446d-968e-116decb2b311`, slug `babbo-osteria`, Rio de Janeiro/Ipanema
- Web `page.tsx` (catch-all `[...slug]`): busca por slug → redireciona ✅
- `App.js:255`: `Restaurant: 'restaurante/:restaurantId'`
- `RestaurantScreen.js:335`: `api.get(\`/api/restaurantes/${restaurantId}\`)` — API espera UUID

### Ações recomendadas
1. API: aceitar slug além de UUID (`WHERE slug = :param OR id = :param`)
2. App: garantir link compartilhado com ID curto (como `generateRestaurantUrl` já faz)
3. Alternativa: endpoint dedicado `/api/restaurantes/lookup?slug=X`

### Arquivos relevantes
- Web: `src/app/api/restaurantes/[id]/route.ts` — `eq(restaurantsConsolidated.id, id)`
- Web: `src/app/restaurante/[...slug]/page.tsx` — busca por slug (funciona)
- Mobile: `App.js:255` — linking config `'restaurante/:restaurantId'`
- Mobile: `screens/RestaurantScreen.js:335` — `api.get(\`/api/restaurantes/${restaurantId}\`)`
- Lib: `src/lib/restaurant-url.ts` — `generateRestaurantUrl()` gera formato correto com ID curto
